# 0004. 캘린더 피드는 주소 안의 별도 토큰으로 확인한다

- 상태: 채택
- 날짜: 2026-11-04

## 상황

[ADR 0003](0003-pwa-and-ics-instead-of-native-app.md)에서 근무 일정을 iCalendar 구독으로 아이폰 캘린더에 보이기로 했다. 피드에는 근무 시각, 메모, 설정에 따라 예상 급여가 들어가므로 아무나 받아 가면 안 된다.

구독 캘린더는 캘린더 앱이 등록된 주소로 GET 요청을 주기적으로 보내는 방식이다. 앱 API처럼 `X-App-Token` 헤더를 붙일 수 없다. 사용자가 정할 수 있는 것은 주소 하나와, 계정 설정에 넣는 사용자 이름·암호뿐이다.

## 검토한 선택지

- **A. HTTP 기본 인증(사용자 이름·암호)**
  - 장점: 비밀값이 주소에 들어가지 않는다. 아이폰 구독 캘린더 설정에 사용자 이름과 암호 칸이 있다.
  - 단점: 기본 인증은 `Authorization` 헤더로 보내는데, 이 헤더는 CloudFront OAC가 Lambda Function URL 서명에 쓴다([ADR 0002](0002-cloudfront-lambda-function-url-oac.md)). OAC가 덮어써서 Lambda까지 닿지 않는다. 쓰려면 피드만 OAC를 거치지 않는 다른 경로로 내보내야 한다.
- **B. 앱 토큰을 주소에 넣기**
  - 장점: 토큰을 하나만 관리한다.
  - 단점: 주소는 캘린더 설정, 동기화된 계정, 복사한 메모처럼 헤더보다 많은 곳에 남는다. 주소가 새면 피드만이 아니라 근무를 고치고 정산을 확정하는 API 전체가 열린다. 주소를 바꾸려면 모든 기기의 앱 토큰도 바꿔야 한다.
- **C. 피드 전용 토큰을 따로 만들어 주소에 넣기**
  - 장점: 주소가 새도 피드를 읽는 것 말고는 할 수 없다. 앱 토큰은 그대로 두고 구독 주소만 새로 만들 수 있다. 헤더가 필요 없어서 OAC 구성을 바꾸지 않는다.
  - 단점: 주소를 아는 사람은 누구나 피드를 받는다. 주소 자체가 비밀번호다.

토큰을 쿼리 문자열(`?token=`)에 넣는 방법도 생각했다. 경로에 넣은 것과 노출되는 곳은 같고, 주소가 `.ics`로 끝나야 파일 형식을 확장자로 판단하는 캘린더 앱도 받아들인다. 그래서 경로에 넣는다.

## 결정

C를 고른다. 구독 주소는 `/cal/<토큰>.ics`다.

- 토큰은 앱 토큰과 같은 방식으로 만든다. 32바이트 난수를 base64url로 쓴 43자이고, 서버에는 SHA-256 해시만 저장한다(`CONFIG` / `TOKEN#cal`).
- 원본 토큰은 설정 화면에서 만들 때 한 번만 보여 준다. 서버에서 다시 꺼낼 방법이 없으므로, 잃어버리면 새로 만든다.
- 새로 만들면 이전 주소는 그 순간부터 404다. 구독을 끊을 수도 있다.
- 토큰이 틀린 요청과 주소 형식이 틀린 요청은 똑같이 404로 답한다. 응답으로 구독 주소가 있는지조차 알 수 없게 한다.
- 피드 응답은 `Cache-Control: no-store`로 보내고, CloudFront `/cal/*` 동작도 캐시하지 않는다. 캐시하면 구독을 끊은 뒤에도 CloudFront가 이전 응답을 내줄 수 있다.
- 오류 로그에는 피드 경로를 `/cal/<redacted>`로 바꿔 적는다. CloudFront 접속 로그는 켜지 않았다.

## 결과

- 주소는 2^256가지라 무작위로 맞힐 수 없다. 요청 제한(WAF)이 없어도 추측 공격은 걱정하지 않는다. 남는 위험은 주소 자체가 새는 것이다.
- 주소는 캘린더 앱 설정에 남는다. 맥에서 구독 위치를 iCloud로 고르면 iCloud 계정에도 저장된다. 주소를 다른 사람에게 보여 준 적이 있으면 설정 화면에서 새로 만든다.
- 설정의 '일정에 예상 급여 표시'를 끄면 피드에 금액이 들어가지 않는다. 주소가 샜을 때 드러나는 정보를 줄이려면 끄고 쓴다.
- 캘린더에 바뀐 근무가 보이기까지는 캘린더 앱이 다시 받아 가는 간격만큼 걸린다. 피드에 1시간 간격을 힌트로 적지만, 실제 간격은 아이폰의 '데이터 가져오기' 설정이 정한다.
- 피드 경로가 OAC를 거치지 않아야 하는 방식(기본 인증 등)이 필요해지면 이 결정을 다시 검토한다.
