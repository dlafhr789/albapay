# 0003. 네이티브 앱 대신 PWA와 캘린더 구독으로 만든다

- 상태: 채택
- 날짜: 2026-11-03

## 상황

이 앱이 해야 하는 일은 두 가지다. 하나는 아이폰에서 근무를 기록하고 급여를 보는 것이고, 다른 하나는 근무 일정을 아이폰 기본 캘린더에 보이는 것이다. 쓰는 사람은 한 명이고, 앱스토어에 올릴 생각은 없다.

아이폰에 직접 만든 앱을 설치하는 방법은 Apple 개발자 프로그램(연 99달러)에 가입하거나, 무료 Apple ID로 Xcode에서 설치하는 것이다. 무료 Apple ID로 설치한 앱은 서명이 7일마다 만료돼서, 그때마다 맥에 연결해 다시 설치해야 한다.

## 검토한 선택지

- **A. 네이티브 iOS 앱(SwiftUI) + EventKit**
  - 장점: 기본 캘린더에 일정을 직접 쓰고 고칠 수 있다. 알림과 위젯도 쓸 수 있다.
  - 단점: 연 99달러를 내거나 7일마다 다시 설치해야 한다. 컴퓨터에서는 쓸 수 없다.
- **B. PWA + iCalendar 구독(.ics)**
  - 장점: 사파리의 "홈 화면에 추가"로 설치하고 서명이 필요 없다. 같은 주소를 컴퓨터 브라우저에서도 연다. 캘린더는 구독 URL 하나를 등록하면 캘린더 앱이 주기적으로 다시 받아 온다.
  - 단점: 캘린더 쪽은 읽기 전용이고, 바꾼 근무가 캘린더에 보이기까지 캘린더 앱의 새로 고침 주기만큼 늦다. 사파리와 홈 화면 앱은 저장소가 따로라서 토큰을 앱에서 다시 넣어야 한다.
- **C. Google 캘린더 API 등 외부 캘린더에 직접 쓰기**
  - 장점: 쓰기가 즉시 반영된다.
  - 단점: OAuth 동의 화면, 토큰 갱신, 외부 서비스 장애를 떠안는다. 아이폰 기본 캘린더에 보이려면 Google 계정을 연결해야 한다.

## 결정

B를 고른다. 캘린더는 근무를 보는 용도라 읽기 전용이어도 되고, 근무를 고치는 일은 앱에서 한다. 비용과 7일마다 다시 설치하는 번거로움이 없고, 컴퓨터에서도 같은 앱을 쓴다.

- 웹앱은 React + Vite로 만들고 `vite-plugin-pwa`로 매니페스트와 서비스 워커를 만든다.
- 서비스 워커는 앱 화면(HTML, JS, CSS, 아이콘)만 미리 받아 둔다. API 응답은 가로채지 않는다. 개인 급여 정보이고, 서버도 `no-store`로 보낸다.
- 새 버전을 올리면 다음에 앱을 열 때 서비스 워커가 바로 바꾼다(`autoUpdate`).
- 캘린더 구독 피드는 다음 단계에서 같은 API에 붙인다.

## 결과

- 인터넷이 끊기면 앱 화면은 열리지만 근무를 읽거나 저장할 수 없다. 오프라인 저장과 동기화는 만들지 않는다.
- 푸시 알림, 위젯, 캘린더에서 일정 고치기는 할 수 없다.
- CSP를 `default-src 'self'`로 두기 때문에, 서비스 워커 등록 코드도 인라인이 아니라 파일(`registerSW.js`)로 낸다.
- 알림이 꼭 필요해지거나 오프라인에서 기록해야 하는 일이 잦아지면 A를 다시 검토한다.
